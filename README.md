# Intent Studio

> **Status — planning documents only.** No code yet; `docs/ROADMAP.md` holds
> the milestone order. Contract: `../../docs/Project_Guides/06_Intent_Studio.docx`.
> A "later product" in the portfolio sequence — sequenced after the earlier
> projects, on the same proof standard.

A service-business brief in; a designed, tested, published website out —
then evidence, not optimism, decides what changes. The model proposes; the
platform enforces: a typed page tree of tested components, approval bound to
an exact immutable candidate, preview-first publishing under scoped
permission with rollback, and a lead inbox that survives a dead notification
provider. First release: one local-service category, one quote-request site
pattern, three pilot clients.

- `docs/END_GOAL.md` — what done means; the invariants; the four required
  failure cases; the ship gate
- `docs/ARCHITECTURE.md` — sources of truth, components, paths, consistency
- `docs/ROADMAP.md` — I1 brief/components → I2 preview → I3 launch →
  I4 review → I5 load + ship
- `docs/DECISIONS.md` — typed page trees, hash-bound approval, one-transaction
  leads, the bounded agent loop — and the guide's open questions

**What counts as done:** clients can publish a site they accept, receive real
authorized inquiries, and understand what the system changed and why — with
the four failure cases drilled and the load evidence committed (machine +
commit on every result).
